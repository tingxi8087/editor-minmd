# 待实现清单

更新日期：2026-10-15。以下是已讨论方案的待办整理与建议顺序，不代表已实现或正在开发。已完成能力见[实现现状](status.md)，方向约束见[设计方案](design.md)。

## 1. 本地文件工作台

- [ ] 打开目录、按需展开文件树，并允许独立打开目录之外的文件。
- [ ] 目录内新建文件/文件夹、重命名；删除进入系统回收站。
- [ ] 多标签：独立正文、修改标记、选区、滚动位置和撤销历史。
- [ ] 关闭单个/其他标签、复制路径、在系统文件管理器中显示。
- [ ] 拖入文件或目录，记录最近文件与目录，快速打开文件。
- [ ] 调整侧栏宽度；维持当前紧凑布局。

验收：目录与单文件入口都可使用；切换、重命名或关闭文件不会串内容、撤销历史或丢失未保存修改；大目录不因一次性递归加载卡住界面。

## 2. Markdown 常用操作补齐

- [ ] 空段落 `/` 插入菜单、键盘选择与过滤。
- [ ] 选中文字后的浮动工具栏。
- [ ] 插入和编辑链接，明确本地文档链接的打开方式。
- [ ] 相对路径图片预览；粘贴/拖入图片，保存到文档旁 `assets/` 并插入相对链接。
- [ ] 未命名文档插图时明确附件落地时机；另存到其他目录时处理资源关系。
- [ ] 表格行列增删、对齐操作；保持普通 Markdown 可表达范围。
- [ ] 代码块语言选择和复制。
- [ ] 标题折叠、专注模式、工具栏隐藏。
- [ ] 粘贴清理规则和真实剪贴板样本验证。
- [ ] 扩充 Markdown 方言样本，完善未知语法保留或转源码编辑策略。

验收：编辑、保存、重开后标题/任务/表格/代码/链接/图片一致；整目录移动后相对资源可用；未支持内容不静默丢失；中文输入法、撤销与选区操作可靠。

## 3. 源码、普通文本与代码

- [ ] 接入 CodeMirror 6；支持 Markdown 源码编辑，替代当前只读原文入口。
- [ ] 明确模式切换的内容版本、光标定位和撤销策略。
- [ ] 普通文本与代码按扩展名选择语言，也可手动切换。
- [ ] 高亮、行号、括号匹配、缩进、折叠、自动换行、多光标。
- [ ] 文件内查找替换、跳转行；后续接目录搜索和结果定位。
- [ ] 编码和换行符显示/选择，支持按指定编码重新打开，例如 GB18030。
- [ ] 大文件策略与实际性能测量，避免把读取限制当作性能承诺。

优先语言：JS/TS、JSON、HTML/CSS、Rust、Python、Shell、YAML。

验收：修改源码再回文档模式内容一致；切换本身不写盘；未知语法有可靠保留路径；普通文件的编辑不误走富文本序列化。

## 4. 文件可靠性与继续工作

- [ ] 文件/目录监听：未编辑文件自动刷新，已编辑文件提示冲突。
- [ ] 冲突对比、重新加载入口；覆盖或合并必须明确用户选择。
- [ ] 可选自动保存，与外部变更保护使用同一保存入口。
- [ ] 定期恢复草稿、异常退出恢复，上次目录/标签/光标位置恢复。
- [ ] 核查应用退出、系统退出、原生按钮关闭与快捷键关闭等路径。
- [ ] 明确并发写入、只读文件、权限错误、磁盘空间不足、链接路径的行为。
- [ ] 清理会话占用与原生已打开文件登记；当前前端未调用已有 `release_document` 命令。

验收：模拟外部编辑、删除、写入失败与强制退出；已保存文件保持可读，未保存内容有清晰恢复或失败边界；自动保存不能绕过冲突检查。

## 5. 外观与背景

- [ ] 自选本地背景，配置位置、模糊、遮罩、纸面不透明度。
- [ ] 背景复制到应用数据目录，提供恢复默认和清理旧图行为。
- [ ] 应用级显示字体、字号、行高；偏好不进入 Markdown。
- [ ] 扩充小窗口、缩放、长文件名、深色弹窗及可访问性检查。
- [ ] 针对 Windows/Linux 确认窗口控制区布局和可拖动区域；不把 macOS Overlay 效果视为跨平台已完成。

验收：主题、背景和字号不改写文件；背景不会遮蔽正文与代码；最小窗口下保存和窗口控制按钮可用。

## 6. 系统入口与开源发布

- [ ] 系统「打开方式」与 Markdown 文件关联。
- [ ] 启动参数、应用已运行时接收新文件、重复打开文件的单实例行为。
- [ ] Windows、macOS、Linux 构建工作流与各平台原生流程验收。
- [ ] 发布安装包，明确签名、公证、校验值和安装限制。
- [ ] 从 npm/Cargo 锁文件生成完整第三方版权及许可文本。
- [ ] 补充贡献说明、问题模板和平台支持表。

验收：系统文件管理器双击/右键打开时落到正确文档；公开产物可下载安装；Release 中真实文件与说明一致，正式发布状态与本地调试包明确区分。

## 推荐推进方式

下一步建议先做目录与多标签的最小可用闭环，再完善图片、链接等 Markdown 常用操作。源码/普通文本编辑随后接入。文件恢复和外部监听应在日常主力使用前补齐，不因功能扩展长期后置。

每项先打通一个真实用户流程，再扩展选项。交付时核对源码、针对性测试、原生桌面行为及实际磁盘内容；不要仅凭构建通过标记完成。

## 明确不做的功能

- 文档内字号、字体、文字颜色、底色、下划线等富排版功能。
- 从 minmd 带入账号、空间、权限、协作、评论和服务端业务。
- 当前阶段的终端、调试器、语言服务器、插件市场和私有文档存储格式。
