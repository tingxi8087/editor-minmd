# 草稿恢复与外部文件修改

更新日期：2026-10-15。当前实现保护未保存正文，并协调磁盘版本变化；保持现有紧凑纸墨布局，只有待恢复、冲突或错误时才显示提示行。

## 草稿保存与恢复

编辑内容自动写入应用数据目录的 `recovery-v1.json`，原 Markdown 仍由用户手动保存。macOS 本次验收的目录为 `~/Library/Application Support/io.github.tingxi8087.editor-minmd/`；其他平台使用 Tauri 的 `app_data_dir()`。

- 输入停止约 650 毫秒后写快照；持续输入时设 3 秒最大等待。失焦时补写，正常保存、关闭和确认重新载入时等待对应恢复记录更新。
- 快照包含原文件快照、当前文本、文件路径、资源基准、修改时间、模式、文件类型、内容权威、光标起点与滚动位置。富文本权威时额外保存正文/基线 JSON，避免恢复时反复序列化；源码权威（含普通文本、代码及不支持的 Markdown）直接恢复字面文本。新增字段可选，兼容早期恢复记录。撤销历史不持久化。
- 状态栏只有在当前正文版本真正完成持久化后才显示“草稿已保护”。较旧写入完成时不会把后续新输入误标为已保护。
- 写入排队串行执行，防止较早快照覆盖较新快照；同一快照不重复写入。同目录临时文件写入、`sync_all` 后替换恢复文件，失败保留上一份成功记录。
- 重启后显示待恢复数量。列表展示文件名、原路径、时间和正文摘要，逐份恢复或经二次确认后丢弃；稍后处理不会删除记录。编辑新文件、保存或关闭其他标签时也保留尚未处理的恢复记录。
- 恢复结果是未保存的普通编辑标签，需要检查后手动保存。若原路径已经在另一个标签打开，恢复为独立的未命名副本，避免覆盖当前会话；相对资源仍有路径基准。
- 恢复时检查原文件，外部已经修改、删除或不可读则保留草稿并提示冲突。恢复本身不覆盖或重新创建原文件。
- 保存完成、明确“不保存”关闭、明确载入磁盘版本后，移除对应活动草稿。恢复记录更新失败时，关闭或放弃内容的操作不会继续；可重试，当前正文仍保留。
- 新的未命名文档会避开已恢复标签的同名名称。

恢复库版本为 1，上限 512 份、序列化总量 128 MB；原文件快照单份最多 16 MB，Markdown 副本最多 32 MB。超限、路径无效或 JSON 结构无效会提示失败，不截断正文。恢复文件损坏、未知版本或无法读取时保留原文件，显示错误并暂停新的恢复库写入，避免覆盖尚未读取的数据；重试会重新读取，仍失败时需保留该文件并处理本地文件问题。

桌面应用启用 Tauri 单实例插件，重复启动转向已有窗口，避免两个正常运行的实例同时写同一恢复库。外部工具手动改写恢复文件不属于协作同步功能。

当前只恢复未保存正文及光标起点/滚动位置，不恢复已保存标签、目录展开、完整选区或撤销历史。应用正常关闭时仍逐份确认未保存内容；自动恢复不替代这个确认。快照有等待与 I/O 时间，强制结束可能丢失最近尚未落盘的输入，不承诺断电级零丢失。

## 外部文件变化

原生 `notify` 监听已打开文档所在的父目录，按单层监听以覆盖直接写入、原子替换、删除和重新创建。通知经约 300 毫秒合并，最大等待 1 秒，再读取已登记文件的真实内容；过滤读取访问事件，避免自身读取触发循环。窗口焦点变化以及每 15 秒调度的补查用于弥补漏报；后台调度、磁盘或系统延迟可能延长实际发现时间。

| 场景 | 行为 |
| --- | --- |
| 文件未修改，磁盘正文变化 | 自动载入新版本，保持标签、阅读模式、光标起点和滚动位置；只重置此标签的撤销历史 |
| 本地存在未保存修改 | 保留当前编辑器、原始保存基线与修改标记，显示冲突提示，提供对比、重新载入、另存副本 |
| 当前应用刚保存 | 磁盘与本次保存快照一致，不重载、不误报冲突、不重置撤销 |
| 文件删除或移动 | 保留当前正文和标签，提示找不到文件，支持重新检查或另存副本 |
| 无效 UTF-8、过大或无法读取 | 保留正文，显示读取错误，不把错误/空字符串当作新内容 |
| 外部文件恢复到原基线 | 清除冲突，允许基于原快照正常保存 |
| 新磁盘版本包含不支持的语法 | 对干净标签进入可编辑源码保护；之后变回可支持 Markdown 时可手动回到文档模式 |
| 监听或检查失败 | 显示对应失败提示，允许重试，仍保留定期补查 |

对比弹窗并排展示本地当前 Markdown 和最近检查到的磁盘正文，目前没有逐行差异着色或自动合并。点击“重新载入”时，脏标签必须再次确认；确认后重新读取磁盘最新版本，不直接使用先前弹窗快照。恢复记录清理失败或文件此时不可读时保留本地编辑。

有外部冲突时普通保存被阻止，可另存副本；底层保存仍比较打开时的原文件快照，不因点击过冲突提示就允许覆盖。保存与检查使用版本校验，保存、关闭、重新载入期间返回的旧检查结果不会覆盖新状态；读取等待期间发生的新编辑也会作为脏内容保留。监听器、定时器和事件订阅随工作台销毁清理。

本轮监听目标是已打开的 Markdown 正文文件。文件树新增/删除、图片资源变化、目录重命名后的路径自动跟随、三方合并与自动保存原 Markdown 尚未实现。文件树仍手动刷新。保存比较和替换之间依然没有跨进程文件锁，不承诺消除所有外部并发写入竞态。

## 实现入口

- [model.ts](../src/workspace/model.ts)：草稿快照与写入队列、恢复/关闭协调、磁盘版本协调。
- [reliability.ts](../src/lib/reliability.ts)：Tauri 可靠性接口和数据类型。
- [reliability.rs](../src-tauri/src/reliability.rs)：本地恢复库、校验、授权恢复、磁盘快照和系统文件监听。
- [ReliabilityPanel](../src/components/ReliabilityPanel/index.tsx)：恢复列表、冲突提示、并排对比和放弃内容的确认。
- [DocumentEditor](../src/components/DocumentEditor/index.tsx)：重载后恢复滚动位置。

技术依据：[notify 的父目录监听说明](https://docs.rs/notify/latest/notify/trait.Watcher.html)、[Tauri 单实例插件](https://v2.tauri.app/zh-cn/plugin/single-instance/)。

## 自测记录

自动测试与构建结果见[实现现状](status.md)。新增测试使用真实 Tiptap 编辑器和工作台组件，Tauri 接口在前端测试中使用替身；Rust 测试使用实际临时目录和系统监听。

覆盖：输入合并与最大等待、后台写入版本标记、写入顺序、具名/未命名恢复、JSON 正文结构、另存为后的图片路径恢复、重名副本、未处理记录保留、损坏库和写入失败、关闭取消与丢弃、重载失败、焦点/通知/定时补查、干净自动刷新、脏内容冲突、删除/重建、未知语法、自己的保存事件、过期磁盘回调和事件清理。组件测试覆盖恢复列表与丢弃确认、冲突对比、重新载入确认和失败重试。

macOS 桌面验收已实际操作：

1. 打开中文路径样例，外部用临时文件原子替换，窗口自动更新且保持干净。
2. 在窗口编辑，再由外部写入新版本，对比窗口同时显示两份内容；取消重载保留本地编辑。
3. 删除并重建验收文件，提示变化但标签和本地正文仍在。
4. 具名与未命名两份验收草稿落盘后，精确定位本项目进程执行 SIGKILL；重新启动提示两份草稿，逐份恢复，原文件仍是外部版本，具名草稿保留冲突。
5. 明确载入磁盘版本并丢弃另一份验收草稿，恢复库变为空，核对原文件未被草稿自动覆盖；再次正常启动不再提示这些旧记录。
6. 最终构建再次创建含勾选任务和表格的结构草稿，SIGKILL 后恢复；核对恢复前后的正文 JSON 与基线 JSON 完全一致，并在桌面确认勾选状态和表格保留。测试后明确丢弃，恢复库为空。

验收仅使用 `artifacts/reliability-check/` 内自建样例。Windows/Linux 原生行为、网络文件系统、操作系统强制注销/关机和断电场景尚未验收。

## 目录变更协调

目录内重命名会等待草稿落盘，同步子标签路径、资源基准、草稿和监听；删除前阻止未保存子标签和待恢复草稿，成功后关闭干净子标签。旧的异步磁盘检查通过版本号失效。具体规则及实测见[目录文件管理](file-management.md)。
