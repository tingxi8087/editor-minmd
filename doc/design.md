# 设计方案

更新日期：2026-10-15。本文记录已确认的产品方向和方案演变；各功能是否完成见[实现现状](status.md)。

## 产品定位

以 Markdown 阅读和写作为核心的本地桌面编辑器，偶尔用于查看普通文本、配置文件和代码。

- 参考 VS Code 的文件工作台布局：目录、文件树、标签、编辑区和状态栏。
- 参考 Notepad++ 的文本操作：语法高亮、查找替换、缩进、跳转等。
- Markdown 参考本机 `/Users/tingxi/appCode/minmd` 的文档编辑器，默认完整所见即所得。
- 使用 Tauri，源码按 MIT 发布，核心编辑和保存不依赖账号、云服务或自建后端。

暂不纳入终端、调试器、语言服务器、插件市场、在线协作、账号、空间权限、评论及服务端文档业务。

## 已确认的编辑方式

Markdown 默认直接编辑排版后的内容。标题、列表、任务、引用、代码块和表格就在文档中操作，不要求用户始终面对 Markdown 标记。

| 模式 | 目标体验 | 当前阶段 |
| --- | --- | --- |
| 文档 | Tiptap 所见即所得编辑 | 已实现基础链路 |
| 源码 | CodeMirror 编辑 Markdown 原文 | 已实现，替代只读原文弹窗 |
| 阅读 | 相同文档排版，关闭编辑辅助 | 已实现基础阅读模式 |

文档与源码模式共享一个文件会话，同一时间只有活动模式可编辑。切换在内存中同步当前内容，不写回磁盘；未修改的切换保留原始文本。两个内核分别管理撤销，另一模式实际修改后重建目标视图的历史；不提供跨模式连续撤销。具体内容权威、原文保留与恢复规则见[源码编辑说明](source-editing.md)。

### Markdown 交互范围

目标保留：

- H1—H6、正文、粗体、斜体、删除线、行内代码、引用和分割线。
- 有序列表、无序列表、可勾选任务列表。
- 表格插入、行列管理和 Markdown 能表达的对齐。
- 代码块、语法高亮、语言选择和复制。
- 链接、图片、本地附件及相对路径。
- 精简格式工具栏、选中文字后的浮动工具栏、空段落 `/` 插入菜单。
- 标题大纲、点击定位、标题折叠。
- 粘贴内容清理：保留受支持的结构，去除字体、字号和颜色等表现样式。

文档格式中明确去掉字体、字号、文字颜色、文字底色和下划线。后续应用级的字体、字号和行高设置只改变本机显示，不写入 Markdown。

不直接带入 minmd 的协作、文档引用、私有提示块和折叠块。复杂合并单元格、列宽等不作为普通 Markdown 的可持久化能力。

## 文件工作台目标

- 可以独立打开某个文件，不强制先打开目录。
- 第一阶段目录工作台按一个窗口一个根目录设计，同时允许打开根目录之外的文件。
- 文件树已支持按需展开、新建、重命名和系统回收站删除；保持紧凑根行按钮与右键/更多菜单，详见[目录文件管理](file-management.md)。
- 多标签独立保存内容、修改状态、选区和撤销历史；支持关闭其他标签、复制路径、在系统文件管理器中显示。
- 支持拖入文件或目录、最近文件和最近目录、快速打开文件、目录搜索。
- macOS 已提供分组选择默认打开方式、逐项结果及系统打开事件排队；非文本类型不修改。Windows/Linux 文件关联与启动参数仍待实现，各平台分别验收，见[文件关联](file-associations.md)。

普通文本和代码已接入 CodeMirror，已实现常见语言高亮、行号、括号匹配、缩进、折叠、查找替换和自动换行。跳转行、显式多光标操作入口及目录搜索仍待补充。默认 UTF-8，后续提供按指定编码重新打开，例如 GB18030。

## 视觉与布局决定

使用 `paper-ink` 和 `paper-ink/icons`，以纸白、墨黑、暖灰和细边界构成界面，链接与状态保留必要语义色。浅色纸面与深色墨纸对应，代码高亮保持可辨识颜色。

**当前以紧凑、扩大正文编辑面积为准。**

- macOS 采用 Overlay 标题栏，系统窗口按钮与新建、打开、保存合成同一行。
- 顶部操作栏 40px，标签与模式栏 32px，格式栏至少 34px，状态栏 22px。
- 左侧工具栏 38px；侧栏通常 190px，窗口宽度不超过 1050px 时为 170px；支持整体隐藏侧栏。
- 文件名完整路径通过悬停提示查看，不再单独占一行路径栏。
- 正文随编辑区域宽度展开，常规内边距为上 18px、左右 28px；小窗口再缩小。
- 正文字号 15px、行高 1.65；标题和列表使用紧凑间距，任务列表不叠加大段落间距。
- 原生窗口按钮留在左上角。当前单行原生标题栏方案仅在 macOS 做过实际验证。

### 背景更换目标

已实现本地图片、模糊和遮罩调整、持久化与恢复默认。图片位于窗口底层，正文固定 92% 纸面保护；不对编辑器应用滤镜/透明度。背景复制到应用数据目录，原生清单独立保存；侧栏不再重复显示「已打开」，文件导航集中于顶部标签。背景位置和纸面不透明度的高级调整尚未开放，详见[背景说明](background.md)。

## 技术与模块边界

| 部分 | 已选方案 |
| --- | --- |
| 桌面壳和系统能力 | Tauri 2 + Rust |
| 前端 | React + TypeScript + Vite |
| 通用组件和图标 | Paper Ink 及其 Tabler 图标出口 |
| Markdown 文档编辑 | Tiptap / ProseMirror |
| 源码、文本、代码编辑 | CodeMirror 6，按文件名识别，语言包按需加载 |
| 全局界面状态 | Zustand；临时编辑状态按会话管理 |
| 样式与路径 | Less、CSS Modules、`@/*` |
| 开源许可 | MIT，第三方依赖保持各自许可 |

遵循 `react-loose-conventions` 和 `frontend-design` 的既定方向。需要路由时使用 Hash Router；当前只有一个工作台页面（含多个文档标签），没有引入空路由或 HTTP 层。使用 npm 和 `package-lock.json`。

责任划分：

1. **文档会话**管理路径、原始文件快照、当前内容版本、修改标记、模式及后续恢复草稿。
2. **编辑视图**管理当前编辑事务、选区、模式内撤销；两个内核不能同时各自持有可编辑正文。
3. **本地文件服务**管理原生对话框、读取、编码、保存、目录访问和后续文件监听。
4. **应用外观**管理主题、侧栏和背景等独立于文档的偏好。

持久化的用户文档是普通 `.md`，Tiptap JSON 用于编辑过程及本机恢复草稿，不成为必须携带的项目格式。

## 保存与兼容原则

所见即所得使用「Markdown → 文档结构 → 编辑 → Markdown」，编辑后允许语法规范化，不承诺所有原始空格、列表符号和空行逐字保留。

- 未修改文档时不重新导出覆盖原文件。
- Frontmatter 独立于正文处理，保留 UTF-8 BOM 和原 LF/CRLF 类型。
- 不支持的语法进入可编辑源码，阻止有损转换；源码保存不经过富文本序列化。
- 保存前核对打开时的磁盘快照；冲突时保留本地编辑并允许另存为。
- 同目录临时文件写入、同步后替换目标；文件监听和草稿恢复已接入，原文件自动保存及更完整并发边界验证仍待补充。

## 早期方案与后续调整

| 早期建议 | 后续决定及原因 |
| --- | --- |
| 用 CodeMirror 统一 Markdown、文本和代码，Markdown 做即时预览 | 用户明确偏好 minmd 的完整所见即所得，因此改为 Tiptap 负责文档，CodeMirror 负责源码和普通文本 |
| 正文居中，宽约 760—860px，较大留白 | 用户认为正文所占区域过少，改为宽度自适应和紧凑排版；旧固定宽度不再是默认方向 |
| 顶部操作、文件标签、路径和格式分别占行 | 去掉独立路径行，将模式入口放到标签行，压缩工具区 |
| 系统标题栏与应用操作栏各占一行 | 用户要求合并，macOS 使用 Overlay 保留原生窗口按钮，把文件操作放到同一行 |
| 建议按基础文本编辑器、Markdown、完善体验依次推进 | 实际先做用户指定的纵向链路：本地 Markdown 打开 → 所见即所得编辑 → 保存 → 重新打开，再按待实现清单扩展 |
